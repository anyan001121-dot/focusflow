# FocusFlow：从功能演示到学习／工作中的实际帮助

日期：2026-09-16。依据：main 源码快照 4b115a40308aaf0d38c3adf726d8be046b4be877、本地练习模式操作、自动化流程测试，以及用户确认的方向「学习／工作任务启动与中断恢复」。

后续更新：本报告记录第一轮走查。第二轮已将暂存输入改为提交后清空的表单，加入可编辑的首页示例，并让计时默认收起；对应旧问题请按历史记录理解。文案保留「出发咯 🌈」等可爱表达，减少压力不等于去掉俏皮感。最新功能说明见 [README](../README.md) 与 [场景对比](before-after.md)。

这里的第一人称是情境模拟，不是 ADHD 亲历陈述，也不代表临床或真实用户研究。ADHD 用户之间差异很大，以下判断是待验证的产品假设。

## 1. 目标用户明确了吗？

原 README 的「ADHD-style friction／overloaded week」有方向，但覆盖过宽，缺少使用时刻。建议第一阶段明确为：

**需要独立完成学习或知识工作、已有明确任务，却经常卡在第一步，或在被打断后难以返回的成年人。**

最先招募：有近期论文、课程作业、求职材料或工作报告任务的大学生、研究生和初入职场者；包含 ADHD 用户，不要求靠诊断标签筛选。筛选依据应是反复出现的任务困难与真实待办。

一句话承诺：**开始不了时，给你一个能做的下一步；被打断后，帮你接回原来的事。**

主要使用时刻：

- 已经打开电脑，却在不同窗口来回切换，迟迟没有碰任务。
- 工作到一半，被消息、突然想起的事或现实需求打断。
- 离开后回来，只记得「我应该继续」，忘了具体做到哪里。

第一阶段不扩展为全能时间管理、家务管理、儿童行为训练或 ADHD 治疗产品。不要把「所有拖延者」当作一个统一人群。

## 2. 逐个功能有没有实际意义？

| 功能 | 可能解决的真实困难 | 目前的风险 | 产品决定 |
| --- | --- | --- | --- |
| Brain Dump | 脑中同时挂着几件事，无法选择 | 整理本身成为新的拖延；AI 猜优先级 | 保留可选入口，单任务可以直接开始；不要求先整理人生 |
| 一个下一步 | 模糊任务没有可执行入口 | 只做到「打开文档」，仍没推进目标 | 核心；必须同时给出可观察的完成标准 |
| 再拆小 | 低能量时降低动作门槛 | 重复拆「打开文档」，陷入准备循环 | 保留；下一轮需验证是否真的变小、是否更相关 |
| 计时 | 外显时间经过 | 从生成建议就开始计时，离开电脑也累计 | 辅助；本轮加入明确暂停，不把计时当专注事实 |
| 中断暂存 | 不必在工作记忆里一直保留新想法 | 稍后列表成为另一堆永远不碰的待办 | 核心配套；专注时收起，结束后可开始或标已处理 |
| Resume | 重新找回任务上下文 | 只显示 AI 步骤，不知道文件与段落 | 核心差异；本轮加入可选返回提示并持久化 |
| 硬规则不切任务 | 避免模型擅自改目标 | 把真实急事也当「不许分心」 | 约束模型，但允许人暂停处理现实需要 |
| 分析看板 | 开发者评估是否有效 | 数字命名夸大：完成轮次被算成成功启动 | 降低优先级；本轮先纠正指标名称，不凭点击证明有效 |

结论：功能组合有合理用途，但**真实价值尚未被验证**。有 AI、计时和看板，并不自动意味着比便签加普通计时器更有用。

## 3. 情境走查：如果我此刻卡住，会怎么用？

### 场景 A：论文今晚要交，我却一直整理桌面

模拟内心：「我知道要写结果，但一想到整篇就不想碰。我不想再填写任务类型、优先级、能量等级。」

理想路径：输入「写论文结果」→看到「在结果标题下，写一句图 1 的主要变化，先留占位数字也可以」→切回文档行动。

走查发现：练习模式第一步会给「打开文档，滚动到相关章节」，后续出现「找出下一步最小的一个具体细节」。这仍把决策交回用户。AI 生成的完成标准以前没有显示，本轮已修复。练习模式的泛化拆解质量仍需下一轮改善，不能把 mock 测试通过说成模型有效。

### 场景 B：写到一半想起要给导师回邮件

模拟内心：「我怕忘，所以想马上切过去；如果记录要填很多项，我干脆不用了。」

实际走查：输入「记得给导师回邮件」后，当前论文步骤保留，暂存列表增加一项。专注时列表内容收起，减少再次吸引注意；结束后可直接开始它。

尚缺：输入发送后仍留在框内，连续误点可能重复添加；需要后续用表单清空或去重优化。没有到点提醒，不能承诺「我会提醒你」。

### 场景 C：要开会／上厕所，二十分钟后回来

模拟内心：「我不是失败了，只是需要离开。回来时别让我重新读整份计划。」

本轮新增：暂停时可留一句「结果章节，接着描述图 1 中的变化」，也可不填直接暂停；任务、步骤、队列、完成标准一起保存。恢复后停留原步骤；显式暂停时段不计入步骤用时。浏览器刷新后的断点也经过本地单用户模式走查。

限制：未按暂停就关页／离开，计时仍可能包含离开时间。公共演示使用临时 session，刷新或新访问的恢复能力不等同于本地个人模式。要对外验证持续使用，需要可靠的个人身份与保存方式。

### 场景 D：做完三个小步骤，但论文显然没写完

模拟内心：「你为什么说我完成论文了？这会让我不相信你。」

本轮修复：只说「完成这一轮小步骤」，不宣称整个现实任务完成；恢复入口不再把已结束的任务显示成仍可继续。页面重新出现输入入口，可以继续写剩余部分或开始下一件事。

尚缺：围绕同一大目标自然继续下一轮，而不是再输入一遍；这是后续比积分、成就或连续签到更值得投入的功能。

## 4. 本轮已实现

1. 首页用一句话明确学习／工作启动与中断恢复。
2. 展示当前步骤的完成标准，并跨中断／恢复保留。
3. 暂停、可选返回提示、持久化恢复、排除显式暂停用时。
4. 暂停期间禁止误操作完成／拆解／覆盖当前任务。
5. 稍后事项可在无活动任务时直接开始或标为已处理。
6. 一轮结束后开放下个任务输入；修正「整件事已完成」文案。
7. 修正看板口径：完成的是步骤轮次；未完成不直接称作放弃。
8. 修正隐私文案：数据库在运行应用的机器；接入模型后文本会发给提供商。

这些改进修补使用路径，没有证明产品能改善 ADHD 症状。

## 5. 下一轮该优先做什么？

**P0：验证建议是否把人带回工作。** 支持「这一步不适合，我已经做到这里」；让用户用一句话纠正上下文。真实模型与练习模式分开评估。围绕论文、作业、报告、求职四类任务建立可观察的样例，而不是增加更多入口。

**P0：自然返回。** 手机／桌面快捷入口和稳定个人保存比复杂看板重要。先验证用户能否想起打开工具，再决定是否做提醒；提醒应由用户主动选择时机，不默认催促。

**P1：降低输入负担。** 首页可给少量可修改的场景示例；暂存输入发送后清空；步骤不合适时允许直接改写。只有实际测试显示需要时才加语音。

**暂缓：** 排行榜、连续打卡、积分、复杂日历、完整项目管理、强制每日复盘。当前没有证据表明这些能解决启动或恢复，且会增加维护工具的负担。

## 6. 怎样知道不是「看起来有用」？

做一次 5–8 人、7 天的探索性测试；这是找问题的小样本，不做疗效推断。让参与者带真实学习／工作任务，用他们原来的便签／待办方法作对照，交替安排两种方式，记录任务难度和当天条件，避免把新鲜感当效果。

每次只追踪四件事：

- **实际开始：** 从请求帮助到第一次可观察的目标行动用了多久？「生成建议」不算开始。打开文件算入口动作，写下一句／改完一项等应另外记录。
- **有效返回：** 中断后是否在同一目标上完成了一次行动？点 Resume 不算成功。
- **额外负担：** 工具内耗时、步骤被改写／拒绝的原因、用户是否觉得多了一件要管理的事。
- **自发使用：** 第 4–7 天，没人提醒时，参与者是否在下一次卡住时再次打开？

探索性决策门槛（研究前约定，不是统计结论）：若多数参与者在至少两次真实情境中报告更容易开始／返回，并且能指出发生的实际动作，继续投入；若主要评价是「很治愈、很好看」却没有行动，优先重做下一步建议；若大家忘记打开，优先改触达入口。

只记录验证所必需的数据；不默认收集论文、邮件正文、诊断资料或屏幕录像。使用自愿观察、行动确认与简短访谈，并允许跳过。

## 7. 依据与证据边界

[NICE NG87 的环境调整说明](https://www.nice.org.uk/guidance/ng87/chapter/recommendations)举例包括减少干扰、较短的专注时段配合活动休息、用文字强化口头要求，并强调按个体需要调整。这支持低干扰、可休息、清晰提示这一设计方向，**不构成 FocusFlow 的效果证据**。

所有具体产品方案、优先级与测试门槛均为本次产品推论。未开展真实 ADHD 用户访谈，未验证真实模型输出质量，也没有对外部署这些变更。
